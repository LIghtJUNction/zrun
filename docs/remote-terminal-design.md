# zrun 原生远程终端设计草案

新增独立的交互会话入口，主机端维持同一个 Linux PTY、进程和终端画面。连接丢失后会话在到期前继续运行，客户端恢复认证连接时拿到最新画面和输入确认位置。现有 MCP 命令协议给脚本和批处理使用，它交付命令结果，交互会话需要额外保持终端状态。

参考 [Mosh](https://mosh.org/) 的本地预测回显、状态同步和漫游。客户端立即显示能安全预测的普通输入和编辑，画面由主机确认后校正。密码输入、关闭回显、全屏应用和难以判断的终端模式先关闭预测。网络往返仍决定服务端实际看到输入和命令结果返回的时间。

## 传输和状态

- 通过 SSH 验证主机与用户并引导会话，数据面使用成熟的加密 UDP 传输。保留 SSH 引导连接以外的恢复凭证，并限制会话存活时间。恢复时验证同一会话权限。
- 输入用序号可靠交付。主机提交输入后记录最高连续序号，重传只补缺失项。客户端断线期间只保留有限待确认输入。始终按序提交输入，输出量与画面拥塞不能阻塞控制键的发送。
- 屏幕更新以代际和基线编号标记。只发送仍有显示价值的更新，丢失基线或终端尺寸变化时请求新快照。实时画面允许跳过中间帧，可靠滚屏历史需要独立协议和限额。
- 已检查的 Project Z 源码中，`zpty`（`66919bc6`）的 `Pty` 提供 PTY 和尺寸变更，`zterm`（`a2074bac`）的 `Terminal` 提供 `view_cell`、`view_position`、`view_row_wrap` 和 `modes`。先验证这些 API 能表达客户端恢复所需的画面和模式，再决定快照序列化接口。`zrun-io` 当前没有 UDP API，传输接入需先验证 reactor 适配。

## Linux 验收

在实际 PTY 对照直连，逐步加入 250/600 ms RTT、2%/10% 丢包、重排和 15 秒断网。分别记录客户端输入到回显、输入到主机确认和命令输出到最新画面三段时间。检查输入重试、切换源地址、断线后恢复同一进程、调整终端尺寸、密码无回显、全屏切换和高输出程序的 Ctrl-C。额外检查发送端、接受端及断线保留的状态上限。
