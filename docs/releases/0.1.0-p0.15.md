# zrun 0.1.0-p0.15

这个 P0 预览版改进了普通多线程计算池的外部任务提交。一个 worker 从非空队列取走任务后，会在执行用户代码之前把队列里剩余工作通知给空闲同伴。外部提交者可以合并对同一队列的重复通知。

在云端 Linux、四 worker、10 万任务的 12 轮配对试验中，spawn/join 吞吐达到原主线的 2.31 倍，自唤醒吞吐达到 5.21 倍。与同机 Tokio 1.54.1 相比，两项吞吐分别为 0.28 倍和 0.59 倍。在 8 个 CPU 上运行 16 个 worker 时，四个提交线程的任务首次执行 P99 从 29.42 µs 升至 83.79 µs。完整性能目标仍在推进。[实验条件、尾延迟与原始数据](https://github.com/LIghtJUNction/zrun/blob/v0.1.0-p0.15/docs/measurements/p0.15-tokio-matrix.md)

新增测试覆盖一批阻塞任务占用全部 worker 时的任务交接。手动工作流可在 Linux、macOS 和 Windows 对比四档规模、五档 worker 的调度性能和回环 TCP。发布资产包括 Linux x86_64 CLI、源码归档、提交号和校验值。
