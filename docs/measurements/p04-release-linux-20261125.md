# Linux p0.4 发行后验证

发行提交 `4d2083e`。在同一台 i9-12900HX 主机固定 CPU 0–15、4 worker，交替运行 p0.3 和 p0.4 GitHub 发行二进制。每轮 256 个客户端批次，每批 16 条，其中 2 条唯一命令和 14 条带同一复用键的命令。每轮按顺序校验全部 4,096 个结果，确认 512 条唯一命令各执行一次、共用命令只执行一次。10 对、20 个独立进程样本全部通过。中位耗时为 p0.3 的 121.48 ms 对 p0.4 的 116.66 ms，比值 0.960 [0.848, 1.023]。两份发行版包含多项差异，不能从这个比值归因单项改动。原始数据位于 `dist/zrun-p04-p03-mixed.jsonl`。

从干净的发行提交构建的 release 调度基准，SHA256 `f4f3fdcea170b7bf74bc6d3d577864f7c2468fc77014cb31a7b7f679179dce59`，于 2026-11-25 00:09（UTC+8）开始 24 小时长测。4 worker 固定 CPU 16–17，单轮 10,000 个任务、每任务 16 次自唤醒，30 秒采样，systemd 进程组 CPUQuota 80% 与 Nice 5。预算用于与同机任务共存。首批已完成，活跃任务清零。长测覆盖调度、任务返回值和内存观测，TCP、定时器压力和命令服务耐久度需独立验证。期满前按运行中记录。日志位于 `dist/zrun-soak-24h-p04-w4`。

## Project Z 互操作

Linux p0.4 发行二进制与 zmcpio 0.5.3（`9c1d8df`）在默认 `$XDG_RUNTIME_DIR/zrun/mcp.sock` 完成 MCP 2025-11-25 初始化、工具发现和 `shell_run` 调用。通过 JSON `args` 传入含空格和星号的参数，shell 按字面值返回。测试同时校验目录 `0700`、socket `0600` 以及正常退出清理。

以 zmem 0.4.5 启动 `zrun --zmem interactive mcp --unix PATH`，另一个 zrun 进程通过 socket 提交命令。用 `/proc` 核对 broker 和受管命令位于同一个 `zmem-interactive-*.scope`，服务正常退出并清理 socket。


## Unix socket 顺序连接复用

候选 release 服务在 CPU 0–15、4 worker 下对比同一客户端逐请求连接和按 64 条一组复用连接。单轮 640 个顺序 MCP 调用，所有输出逐项校验，同键命令仅执行一次。20 对独立服务进程，先后顺序平衡后固定随机。连接数从 640 降到 10，中位耗时从 26.18 ms 到 20.09 ms，比值 0.767 [0.690, 0.838]。结果限于该顺序复用负载。原始数据位于 `dist/zrun-mcp-keepalive-load.tsv`。

内置 CLI 接入后，使用 release 客户端提交 2,048 条 JSONL 命令，形成 128 个 MCP 请求。用 `strace -e connect` 确认新服务完成两次连接，p0.4 旧服务完成 128 次连接。两次运行均验证全部输出，底层命令执行一次。另用测试端点在完整接收首个请求后断开，客户端返回错误，跟踪只出现一次连接。
