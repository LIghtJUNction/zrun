# 本地就绪队列空提示实验

候选 `03af0d7` 使用锁内更新的空队列提示。运行中的 worker 可在第一次扫描跳过看起来为空的自己的队列；声明即将休眠后仍加锁检查。窃取其他队列的路径和批次保持原样。与之前的[窃取空队列提示](ready-queue-linux-20261124.md)相比，本轮只有队列所属 worker 使用提示位。

对照为 `483cfb7`，候选相对对照仅有队列提示改动和中间提交的文档更新。Linux x86_64、Intel Core i9-12900HX、Rust 1.100.0、固定 CPU 0–15。每格 100,000 任务、10 对交替运行的独立 release 进程。160 个基准样本和 81 项工作区测试均通过。下表为候选/对照的中位数比及配对 bootstrap 95% 区间。

| Worker | 创建回收吞吐 ↑ | 唤醒吞吐 ↑ | 每次唤醒 CPU ↓ | 自唤醒 P99 ↓ | 跨线程 P99 ↓ |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 4 | 1.053 [1.002, 1.132] | 1.216 [1.148, 1.270] | 0.802 [0.775, 0.869] | 0.951 [0.769, 1.224] | 1.169 [1.106, 1.525] |
| 16 | 1.074 [0.990, 1.251] | 1.045 [1.028, 1.145] | 0.970 [0.912, 0.999] | 1.071 [1.015, 1.148] | 0.988 [0.930, 1.040] |

4 worker 唤醒吞吐和 CPU 开销受益，说明本地队列加锁是值得优先测量的路径。该实验同时改变了 worker 进入窃取的时机，无法单独量化锁的成本。4 worker 的跨线程 P99 与 16 worker 的自唤醒 P99 回退，候选留在实验提交。原始样本位于 `dist/zrun-ownhint-*`。

4 worker 跨线程 P99 独立复测 20 对进程，40 个样本均通过正确性检查，比值为 1.234 [1.062, 1.362]。


## 仅在已有本地续跑任务时跳过

候选 `b1e5ba5` 把提示位限制在本地仍有续跑任务时。每轮最多因此多运行一个本地任务，下一轮必须加锁检查。没有续跑任务时，直接检查自己的队列，再窃取或休眠。与前一轮使用相同的对照、环境、任务规模与配对方法。160 个样本和 81 项工作区测试均通过。
