# Pool 窃取批次与唤醒 CPU 开销

采样对象为 `483cfb7`，对照 Tokio 1.54.1。同一 release 二进制在 Linux x86_64、i9-12900HX、Rust 1.100.0、CPU 0–15 上运行。4 worker、100 万任务、每任务 16 次自唤醒。每套运行时采样一次，均完成 1,600 万次唤醒及任务结果校验。进程 CPU 时间为 zrun 每次 288 ns、Tokio 每次 138 ns。zrun 用户态周期采样中 `SharedPool::next_task` 占 28.9%，`TaskRef::poll_budget` 占 13.5%，`SharedPool::publish` 在提交线程占 8.2%。指令级采样将 `next_task` 热点定位到本地和其他 worker 的队列锁附近。采样有指令偏移，无法据此推断某一条指令的精确周期数。

候选 `59714af` 将窃取成功后可同时带走的额外任务上限从 8 提到 32，仍为原队列保留至少一半余项。每格 100,000 个任务、10 对交替执行的独立进程，共 160 个样本全部通过。候选/对照中位数比与配对 bootstrap 95% 区间如下。

| Worker | 创建回收吞吐 ↑ | 唤醒吞吐 ↑ | 每次唤醒 CPU ↓ | 自唤醒 P99 ↓ | 跨线程唤醒 P99 ↓ |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 4 | 1.090 [1.032, 1.143] | 1.097 [1.033, 1.266] | 0.912 [0.832, 0.954] | 0.985 [0.855, 1.100] | 1.227 [0.938, 1.561] |
| 16 | 1.003 [0.942, 1.071] | 1.050 [1.016, 1.083] | 1.027 [0.998, 1.045] | 1.092 [1.007, 1.145] | 1.009 [0.940, 1.157] |

4 worker 的吞吐和 CPU 开销受益。16 worker 的自唤醒 P99 回退，候选留在实验提交。原始样本与采样位于 `dist/zrun-steal32-*` 和 `dist/zrun-wake-profile-*`。执行器 16 项测试通过。

4 worker 用 20 对独立进程复测跨线程唤醒 P99。40 个样本均有效，比值 1.297 [1.140, 1.486]。扩大窃取批次带来的吞吐改善不足以抵消尾延迟回退。
