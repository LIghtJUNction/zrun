# Linux 命令服务初次验收

环境为 Intel Core i9-12900HX、24 逻辑 CPU、Linux 7.3.5-arch1-1、Rust 1.100.0 和 cargo release 配置。IPC 使用本机 Unix socket 和 MCP 2025-11-25。每个样本启动新服务，用 1,000 个同时释放的客户端任务分别提交同一个 `sleep 0.05; printf zrun`。每种配置 5 次，交替执行对照与复用模式。每条请求都校验 RPC ID、退出结果和 stdout。

## 1000 客户端

复用模式带同一输入版本和 30 秒 TTL。结果如下，时间为客户端发起整批并发至全部完成。RSS 是约 5 毫秒间隔采样的服务进程峰值，括号为 5 次的范围。

| 模式 | 实际执行 / 共享 | 耗时中位数 | 请求延迟 P99 中位数 | 峰值 RSS 中位数 |
| --- | --- | --- | --- | --- |
| 独立执行 | 1,000 / 0 | 1.718 s（1.713–1.740） | 1,670 ms | 9,404 KiB（9,400–9,416） |
| 合并在途 | 1 / 999 | 0.120 s（0.109–0.123） | 120 ms | 9,976 KiB（9,872–9,984） |

两个模式都观察到 3 个服务线程。独立执行有 32 个直接子进程同时存在，与并发执行上限吻合，至少需要 32 个批次完成 50 毫秒的等待工作。复用模式只观察到 1 个直接子进程，服务 RSS 在这一负载下仍略高于独立模式。表中 RSS 只覆盖服务本身，未汇总子进程和内核缓冲区。

## 连接内存调整

第一轮测量的峰值 RSS 中位数分别为 21,536 KiB（独立）和 22,116 KiB（复用）。Rust 编译器类型布局显示每个 HTTP handler future 占 7,136 字节。固定读取缓冲区跨过 await，导致等待命令结果的连接也保留它们。缓冲区移到实际读取时使用的栈帧后，handler future 为 928 字节。再次运行相同的负载，峰值 RSS 中位数降至上表数值。复用模式延迟样本的前后分布部分重叠，这项改动的确认收益是服务 RSS。

可用 [agent-load.py](../../scripts/agent-load.py) 重跑。原始样本和 Rust 类型布局保存在本机 Project Z 的 dist 记录中。

## 已跑通的入口

- CLI 的真实伪终端保持工作目录和 shell 变量。
- 官方 MCP Python SDK 1.27.2 对 stdio、TCP 和 Unix socket 分别完成 2025-11-25 初始化、工具发现、命令调用。
- CLI 集成用例覆盖跨入口缓存、zguard 配额、独立命令执行、二进制输出、超时、HTTP 分块和 socket 退出清理。
- 实际加载 zplugin ABI v1 示例动态库，检查允许与拒绝行为。
- 用 zmem 0.4.5 启动命令，从命令自身读到 `zmem-interactive-*.scope`。
- 现有单线程调度器的显式百万任务回归通过。运行时相对 Tokio 的完整性能矩阵沿用既有门槛。

## 4 worker 复验

同一 Linux 环境使用 release 构建与 `ZRUN_WORKERS=4`，分别运行 3 轮 1,000 客户端。独立模式每轮实际执行 1,000 次，中位耗时 1.724 秒。复用模式每轮执行 1 次并合并 999 个请求，中位耗时 0.129 秒。采样最多同时观测到 32 或 1 个直接子进程，两个模式各有 7 个服务线程。复用模式峰值服务 RSS 中位数为 9,976 KiB。原始样本在 `dist/zrun-agent-load-4-worker-release.jsonl`。

## 命中时跳过缓存键的 Arc 分配

候选 `5a2892a` 把临时缓存键内联到已授权的提交记录，仅在新建在途任务时分配用于保留的 Arc。与 `d38ba80` 的 Linux release 版固定 CPU 0–15、4 worker，16 对交替启动的 broker，每轮 1,000 个相同可复用请求。32,000 个请求均验证响应，每轮只实际执行一次。下表为候选/对照的中位数比与配对 bootstrap 95% 区间。

| 请求吞吐 ↑ | 每轮 P99 ↓ | broker 采样峰值 RSS ↓ |
| ---: | ---: | ---: |
| 1.002 [0.959, 1.030] | 0.997 [0.971, 1.042] | 1.029 [1.026, 1.033] |

工作区测试、严格 Clippy 和真实 Valkey 冒烟测试通过。端到端吞吐和尾延迟未测到明确收益，采样峰值内存增加，候选未合入。原始数据在 `dist/zrun-stack-key-reuse.jsonl`，实验补丁在 `dist/zrun-stack-key-experiment.patch`。
