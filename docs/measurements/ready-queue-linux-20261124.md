# Linux 就绪队列扫描实验

基线 `acef955`。Intel Core i9-12900HX，Linux 7.3.5-arch1-1，Rust 1.100.0 release。调度样本固定 CPU 0–15。每格使用交替先后顺序的独立进程。报告给出候选相对基线的中位数及配对 bootstrap 95% 区间。

## 候选筛选

`6726300` 每次从本 worker 队列预取最多四个任务，并为窃取保留至少一半余项。五档 worker、十万任务的创建与回收、唤醒吞吐和 CPU 开销均未发现稳定改善。16 worker 创建与回收为 0.920 [0.807, 1.023]。该改动留在实验提交。

`fc3b6a0` 根据队列提示位跳过窃取扫描中的空队列。16 worker 创建与回收吞吐为 1.383 [1.283, 1.479]，每次唤醒的 CPU 开销为 0.524 [0.501, 0.610]。跨线程 P99 独立复测为 1.089 [1.009, 1.133]。在 16 worker 的百万任务采样中，取任务函数的排他 CPU 时间从 5.856 秒降到 0.742 秒，系统调用仍是主要开销。上述候选用于定位热点。

队列提示位仅在持有该队列锁时更新。后续候选把跳过空队列限定在首次扫描。worker 宣告将要休眠后仍执行完整扫描。该版本需完成独立编译和对照。

## 空队列提示的调度样本

每档 100,000 任务，10 对独立进程。候选为只用于定位的 `fc3b6a0`。

## 2,000 路请求和跨传输缓存

现有主线的 Linux CLI 在 CPU 16–17 用 4 worker、2,000 路 Unix socket 请求运行三对独立进程。重复命令声明固定输入版本和有效期。独立执行模式每轮实际执行 2,000 次，复用模式每轮实际执行 1 次，其余 1,999 次由在途合并或已完成缓存交付。请求吞吐的三轮中位数为 201 与 1,273 请求每秒，服务进程采样峰值 RSS 的中位数为 7,496 与 6,824 KiB。该内存口径为单个服务进程。

官方 SDK 验证同一个服务中 Unix socket 首次执行，TCP 与 stdio 转发命中同一缓存。三条入口共用 zguard 配额，四次相同工具请求的第四次被拒绝。
