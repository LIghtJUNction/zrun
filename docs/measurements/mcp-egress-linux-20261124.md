# Linux MCP 出站缓冲

比较旧版 `8ec939f` 与新版 `a54060643cf437c70a7eef076abc48e12e1f2f04`。两版使用 Rust 1.100.0 release 构建，同机运行于 Linux 7.3.5-arch1-1、Intel Core i9-12900HX，服务和客户端固定在逻辑 CPU 0–7。每个样本启动新服务，两版先后顺序逐轮交替。

## 不同命令的大输出

每个用例执行 192 条不同命令，stdout 和 stderr 各含 64 KiB 数据。客户端发完请求后暂停主动读取响应体。用独立记录核对 192 条命令都实际完成且只执行一次，再等待 100 ms 采样服务 RSS。最后读取所有结果，核对每条请求的 RPC ID、退出码、状态、完整 stdout/stderr，以及文本和结构化结果的一致性。每对样本传回的字节数相同。

| 场景 | 配对轮数 | RSS 中位数，旧版 → 新版 | 新版/旧版 RSS 95% 区间 | 整批用时中位数，旧版 → 新版 |
| --- | ---: | ---: | ---: | ---: |
| 1 worker，192 个单条请求 | 10 | 155,032 → 56,522 KiB | 36.34%–36.49% | 0.912 → 0.830 s |
| 4 worker，12 个 16 条批次 | 5 | 161,540 → 50,084 KiB | 30.63%–31.31% | 0.758 → 0.772 s |

两组分别交付 151,083,922 和 151,064,594 字节 JSON。区间用 5,000 次配对 bootstrap 计算。单 worker 的整批用时比区间为 0.878–0.971，四线程包含 1。绝对用时包含 100 ms 固定停顿、子进程和客户端解码。

新版共用 32 MiB 的结果编码预算。为批次一次预留缺失的全部编码，空间不足时保留原始结果并等待。避免多条回复各占一部分预算，再相互等待剩余空间。相同结果的现有编码由多个回复共享。最后一条写入完成、失败或被取消时释放预算。测试中主动关闭 42 条尚未读完的连接后，尚在等待的 6 条请求全部收到完整响应。原始 stdout/stderr、消息元数据和内核 socket 缓冲区与该编码上限分别计量。

```sh
taskset -c 0-7 python3 scripts/agent-load.py --binary /path/to/new/zrun \
  --distinct-output-baseline /path/to/old/zrun --agents 192 --rounds 10
```

## 回归

普通千并发独立执行和复用各跑 5 对样本，两组整批用时和峰值 RSS 的比值区间均包含 1。复用组仍为 1 次执行、999 次合并。另跑 5 对 4 worker、192 客户端读取同一大结果的用例，每条结果均完整交付。官方 MCP Python SDK 1.27.2 的 TCP、Unix 和 stdio 转发复验通过。工作区 63 项测试通过、1 项跳过，严格 Clippy、rustdoc 和 release 构建通过。

原始样本在 Project Z 的 `dist/zrun-wire-{distinct-192-w1,distinct-batch-w4,shared-192-w4,ordinary-1000}.jsonl`。二进制 SHA-256 为 `9d106644860537372c5b1741f3e70426a6e72b79e6ce72cfea60a9e6f7715fb5` 和 `3acb34b64888925d48d86430878beab5ae60b28df8876bae96c03924cdc3bc97`。
