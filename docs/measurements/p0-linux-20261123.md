# zrun P0 验收与首次基准

日期：2026-11-23，Asia/Taipei。实现提交：`12e6421ddfc898658ab59f97e922979e85d8b597`。设计提交：`b33e0d087102fdf8c33adc12fc2e49fe36a53dfb`。

## 结论

P0 已可运行：独立单线程执行器、跨线程注入与唤醒、结果 Join、显式取消、定时器和关闭路径均有实际测试。核心不依赖 Tokio；Tokio 1.54.1 只用于独立比较器。首次单线程性能实验没有达到任何一项普通或挑战门槛，不能宣称比 Tokio 更快、更省每任务内存，也不能据此替换现有服务的主运行时。项目未部署、未公开发布。

这里的“运行时”负责保管尚未完成的 Future、在其被唤醒后再次 poll，并在没有可运行任务时等待。P0 用互斥锁保护任务状态和队列，用单一 poll 所有者保证同一个 Future 不会被同时执行。计时器只登记截止时间；它不为每个 sleep 创建线程。模块与不变量见 [设计](../design.md)，后续阶段见 [计划](../plan.md)。

## 实验条件

比较在共享 Linux 沙箱执行，CPU 型号为 Intel Xeon Platinum 8573C，允许 9 个逻辑 CPU；父进程和每个子进程均绑定 CPU 4。内核为 6.18.57，未控制宿主机负载、CPU governor 或频率，不将这些数字解释为独占裸机的硬件上限。采样时间为 2026-11-23 20:58:39 至 21:02:37（Asia/Taipei）。

两个引擎使用同一个 release 比较器、相同 Future 实现和任务规模，交替先后顺序，每个样本启动新进程。任务规模为 1,000、10,000、100,000、1,000,000；每格 10 轮。yield 场景每任务自唤醒 16 次；延迟最多记录每进程 10,000 个原始值。每格中位数及配对比值采用 5,000 次 bootstrap，报告 95% 区间。完整 95% 区间越过门槛才记为通过；没有多重比较校正，因此各格属于探索性比较。[统计定义与复现协议](../benchmark-protocol.md)

## 性能结果

表中比值均为 **zrun 中位数 / Tokio 中位数**，方括号是配对比值的 95% bootstrap 区间。吞吐希望比值更高，内存希望更低。普通门槛分别为吞吐至少 1.20、每任务内存至多 0.85。延迟一栏列出各进程 P99 的跨进程中位数，不是把所有原始延迟合并后的 P99。

| 任务数 | spawn/join 吞吐比 | 自唤醒吞吐比 | Pending 每任务 RSS 比 | 自唤醒 P99：zrun / Tokio |
| ---: | ---: | ---: | ---: | ---: |
| 1,000 | 0.591 [0.544, 0.643] | 0.357 [0.319, 0.443] | 1.354 [1.354, 1.354] | 0.554 ms / 2.429 µs |
| 10,000 | 0.502 [0.469, 0.534] | 0.353 [0.323, 0.422] | 1.324 [1.324, 1.324] | 5.508 ms / 2.648 µs |
| 100,000 | 0.446 [0.300, 0.498] | 0.346 [0.323, 0.367] | 1.297 [1.297, 1.297] | 55.367 ms / 2.830 µs |
| 1,000,000 | 0.313 [0.255, 0.498] | 0.229 [0.210, 0.243] | 1.347 [1.347, 1.347] | 702.558 ms / 2.851 µs |

百万规模的绝对中位数：zrun spawn/join 609,542 任务/秒，Tokio 1,950,122；zrun 自唤醒 2,790,092 次/秒，Tokio 12,206,004；zrun Pending RSS 355.672 字节/任务，Tokio 264.008。这里的内存值包含该测试持有的结果句柄及分配器/页驻留影响，不等于 Rust 任务结构体的 `size_of`。

运行时创建的 RSS 增量中位数约为 zrun 98,304 字节、Tokio 118,784 至 122,880 字节，但各格的区间未完整满足“至多 80%”门槛，因此仍不记为通过。启动页驻留会造成噪声；原始差值、空值及负值没有被删去或伪装成零。

唤醒延迟测的是“任务调用自己的 waker 到同一任务再次被 poll”。P0 将唤醒任务放回 FIFO 队尾，因此大量已就绪任务会排在它前面；这与 [执行器的 `push_back` / `pop_front`](../../crates/zrun-executor/src/lib.rs) 一致，是解释规模效应的实现依据，不是外部网络响应延迟的实测结论。优化应分别比较公平轮转、有限本地快速再调度、队列/锁竞争和任务分配成本；不能通过删除正确性检查或把自唤醒延迟冒充 TCP 延迟来达标。

所有 20 个可评估指标格的普通与挑战结果均为 false。workers=2/4/8/16 显式为 unsupported；调度 CPU 隔离开销、TCP 吞吐与 TCP P99 尚未测量。`yield_ns_per_op` 只是包含测试开销的墙钟时间，不是隔离 CPU 开销。机器可读结果见 [汇总 JSON](p0-linux-20261123.json)。

## 短测与未完成门槛

120 秒短测在第 30 秒后的 18 次 RSS 采样均为 5,300,224 字节，OLS 斜率为 0；这只描述这次短测的页驻留，没有证明长期无泄漏。它没有覆盖 24 小时、TCP、随机计时器/取消混合压力。`duration_24h_covered=false` 与 `full_soak_gate=not_evaluated` 均保留在报告中。

Loom 模型尚未实现/执行；Miri 不替代 Loom 的交错探索。多线程调度、I/O reactor、异步 TCP、跨平台行为和 24 小时稳定性均为后续阶段。现有上层库接入应从单线程、无网络和无阻塞系统调用的清晰边界开始，不能直接替换 ssmcp 的 Tokio 网络/进程运行时。
