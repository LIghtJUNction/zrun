# 定时器队首通知

比较 `f25f1e0` 与 `6c3d50d` 的定时器驱动。Linux x86_64、Intel Core i9-12900HX、Rust 1.100.0 release，固定 CPU 2。每个进程注册 100,000 个未来 600 秒的定时器，确认全部保留，再按注册顺序或倒序取消并确认条目归零。每种方式 20 对进程，平衡后随机先后顺序。通知回调只增加一个原子计数。测量从注册开始到取消结束，统计不含驱动关闭。

| 取消顺序 | 对照通知次数 | 候选通知次数 | 对照总耗时 | 候选总耗时 | 耗时比及 95% 区间 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 按注册顺序 | 200,000 | 100,001 | 31.76 ms | 31.72 ms | 0.999 [0.944, 1.029] |
| 倒序 | 200,000 | 2 | 38.89 ms | 37.54 ms | 0.965 [0.957, 0.985] |

所有样本均通过。注册顺序取消反复删除队首，每次都需要更新驱动；倒序只在首次注册和最终取消时改变队首。该微基准的回调未取代实际停车和唤醒，无从估算系统调用或应用侧收益。10 次无探针的工作线程取消回归验证了短定时器不会提前触发、长定时器取消后归零。源码和原始样本位于 `dist/zrun-timer-notify-probe.{rs,tsv}`。
