# Linux 调度候选与多 worker 回归

本轮保留对照工具和数据，调度候选留在实验提交。

基线 `6b4fdbc` 包含 Unix 文件描述符可写通知和子进程退出监听。优化候选的干净源码为 `041926f`。同一台 Intel Core i9-12900HX、Linux 7.3.5-arch1-1、Rust 1.100.0 release。调度对照固定 CPU 0–15，TCP 服务端固定 CPU 0–7、客户端固定 CPU 8–15。每格 10 对独立进程，逐轮交替先后顺序。比值区间为配对 bootstrap 95% 区间。

没有等待定时器时，驱动直接跳过读时钟和定时器表锁。最先插入或最后移除定时器在表锁内更新提示位。新定时器仍在发布后通知驱动，线程准备休眠时仍锁表查询实际最近期限。单线程 `Runtime` 每次出队最多 poll 同一任务五次。每轮最多出队 38 次，最多 190 次任务 poll 后推进 I/O。根 Future 收到通知时提前结束本轮任务批次。

## 实验筛选

旧版 4 worker 热点采样中，就绪任务发布和选取占自唤醒负载约 44% 的排他 CPU 样本。创建与回收负载中，选取就绪任务和系统调用各占约三成；任务登记回收也出现在调用图中。百分比描述单次采样，收益以重复对照为准。

多 worker 本地批次加长后，16 worker 创建与回收吞吐下降约 9%，跨线程 P99 上升约 22%。另一版以读取停车标记跳过部分原子交换，8、16 worker 创建与回收吞吐分别下降约 6%、9%。两项调度实验均已撤回。下文的 `041926f` 将单线程出队后的内联复 poll、空定时器短路径和队列压力回归测试组合起来测量。

## TCP

1、4、8 worker 与主线和 Tokio 各做了 240 个 Linux 回环 TCP 样本，全部通过帧校验。对 Tokio 的 24 个指标格有 3 个达到普通目标。8 worker、64 连接 × 64 B 的吞吐为 1.321 [1.061, 1.517]，往返 P99 为 0.501 [0.385, 0.727]，两项同时过线。同为 8 worker 的 128 连接 × 4 KiB，往返 P99 为 0.616 [0.553, 0.836]。单连接、64 B 的 4 和 8 worker 吞吐仍低于 Tokio，约为 0.76 倍。

主线对照中，4 worker、单连接 × 64 B 的首轮吞吐比值为 0.968 [0.805, 0.99988]。20 对样本复测的比值为 1.057 [0.959, 1.080]，首轮回退未复现。

## 缩小优化范围后的复测

`084e743` 将空定时器短路径限定到调用线程驱动的 Runtime。2 worker 的创建与回收吞吐恢复到 0.984 [0.918, 1.047]，16 worker 仍为 0.933 [0.907, 0.959]。

`b44f907` 将 Pool 的调用线程简化为只驱动根 Future。16 worker 创建与回收首次测得 0.972 [0.930, 1.016]。独立复测中，2 worker 创建与回收为 0.958 [0.899, 0.996]，16 worker 唤醒吞吐为 0.955 [0.934, 0.971]，CPU / wake 为 1.033 [1.010, 1.071]。4 worker 自唤醒 P99 为 1.225 [1.095, 1.320]。该版也保留在实验提交。

主线二进制与自身比较的 20 对样本中，16 worker 创建与回收为 1.006 [0.883, 1.083]，唤醒吞吐为 0.982 [0.797, 1.209]。这一轮观察到明显运行间波动。采纳判断以独立复测和多指标的结果为准。

## 候选的正确性和命令服务

74 项常规测试、11 项 Loom、39 项 Miri、严格 Clippy、rustdoc 和 7 项基准统计脚本自检通过。Miri 使用 `nightly-2026-11-24`。单 worker 与 8 worker 的百万任务通过。8 worker 30 秒短测完成 13,830,000 项，活跃任务归零。原有 `42d95e8` 的 4 worker 24 小时长测仍在运行。完整任务规模矩阵、跨平台和长期稳定性待验收。

真实 PTY、zguard 单元测试、zplugin 允许和拒绝用例、zmem cgroup 归属通过。MCP 官方 SDK 1.27.2 通过 Unix、TCP 和 stdio 转发三路运行。千并发 Unix 用例的对照组执行 1,000 次命令，开启可安全复用后实际只执行 1 次，其余 999 次合并。核心与 CLI 的常规依赖图不依赖 Tokio。
