# Linux 原子任务状态对照

比较 `e070019` 与 `9c6503d7d824ecfc54bd6207b037c4e7eb85e343`。两版在同一台 Intel Core i9-12900HX、Linux 7.3.5-arch1-1 上以 Rust 1.100.0 release 构建。运行时比较器固定在逻辑 CPU 0–15，每个配置 10 对独立进程，先后顺序逐轮交替。区间采用配对 bootstrap 95% 区间。

## 两版 zrun

唤醒把通知位写入原子状态，同时判断是否需要发布 runnable。内联复 poll 用原子操作检查通知与取消，并保留已经取出的 Future。每轮结束时仍在互斥锁内归还 Future，随后发布空闲或已入队状态。此前的互斥锁同时保护 Future 和通知，每次唤醒与每次内联复 poll 都会获取它。

1、4、8 worker 和 10,000、100,000 tasks，测试 spawn/join、唤醒吞吐与 CPU、自唤醒 P99、跨线程 P99、等待中内存。600 个进程样本全部通过正确性校验。100,000 tasks 的自唤醒结果如下，数值为新版除以旧版。

| worker | 吞吐比值 | CPU / wake 比值 | 自唤醒 P99 比值 |
| ---: | ---: | ---: | ---: |
| 1 | 1.182 [1.068, 1.331] | 0.847 [0.751, 0.936] | 0.663 [0.552, 0.750] |
| 4 | 0.978 [0.933, 1.065] | 1.016 [0.929, 1.062] | 0.684 [0.650, 0.797] |
| 8 | 1.050 [0.985, 1.085] | 0.986 [0.899, 1.043] | 0.770 [0.691, 0.860] |

10,000 tasks 下的三个自唤醒 P99 也下降。跨线程 P99、spawn/join 吞吐以及等待中 RSS / task 均未测得稳定改善。1 worker、100,000 tasks 的 CPU 降幅来自相同负载的进程 CPU 实测，未细分到函数。

## 同版对 Tokio

候选 `9c6503d` 和 Tokio 1.54.1 在 1、4、8 worker、100,000 tasks 下的 360 个进程样本均通过校验。21 个指标配置中，3 个自唤醒 P99 与 1 worker 的空闲增量 RSS 通过严格验收。下表为中位数 zrun/Tokio 比值。

| worker | spawn/join 吞吐 | 唤醒吞吐 | CPU / wake | 跨线程 P99 |
| ---: | ---: | ---: | ---: | ---: |
| 1 | 0.617 | 0.952 | 1.045 | 2.174 |
| 4 | 0.279 | 0.196 | 4.539 | 1.829 |
| 8 | 0.271 | 0.303 | 3.743 | 1.950 |

1 worker 的唤醒吞吐区间为 0.815–1.015，尚未达到 1.2 的门槛。多线程 CPU 与跨线程 P99 仍超出门槛。

同一候选的 TCP 回环运行了 1、4、8 worker 的四种连接及帧大小，240 个样本均通过回显校验，24 个指标配置均未通过严格领先门槛。另对早前通过的 8 worker 两个 P99 用例直接做了两版 zrun 的配对对照，共 40 个样本。两格吞吐及 P99 的区间均包含 1。该 A/B 的基线二进制来自 `7501a32`，它到 `e070019` 的变化未涉及 TCP 比较器、运行时或锁文件。

## 生命周期验证

普通工作区测试通过 66 项、跳过 1 项，严格 Clippy 与 rustdoc 通过。Loom 6 项通过。其中 3 项使用原子状态实现，覆盖重复唤醒与归还 Future、内联复 poll 对唤醒发布的可见性，以及 abort、shutdown 和 Pending 的所有权竞争。其余 3 项覆盖现有的执行器休眠握手。模型未覆盖完整线程池及 I/O 生命周期。独立的 8 worker 百万任务运行完成 1,000,000 次 spawn/join，校验和 499999500000，剩余任务为 0。4 worker 的 Unix 千并发复用场景执行 1 次、合并 999 次。官方 MCP SDK 的 Unix、TCP 和 stdio 转发通过复验，受管命令的实际 cgroup 也确认由 zmem 创建。

TCP 原始数据在 `dist/zrun-atomic-schedule-tcp/report.json` 和 `dist/zrun-atomic-schedule-tcp-pairs/report.json`。
