# p0.8 调度器 Tokio 对照

候选为 `e2a2d96853661f34d50dedf68f2af7c548429f10`。Linux 7.3.5、Intel Core i9-12900HX、Rust 1.100.0 release，Tokio 1.54.1。两套运行时使用同一二进制，进程固定在 CPU 0–15。1、4、8、16 worker 分别运行 10,000 和 100,000 任务，每格 10 对独立进程，逐轮调换两侧顺序。960 个样本全部通过各场景的正确性检查。以下 95% 区间来自 5,000 次配对 bootstrap。

16 worker 的跨线程 P99 中位数为 3.51 µs 和 39.60 ms。场景先等待所有任务注册，再从专用线程集中唤醒，延迟包含排队。该比值仅覆盖这次突发负载。调度指标共 24/56 过线，TCP、其余任务规模和其他平台需要单独验证。

用同一二进制另采 3 对 16 worker 自唤醒进程，每个进程校验 100,000 个任务和零活动任务。以 `cycles:u` 在 CPU 0–15 采样，zrun 的 `SharedPool::next_task` 占 60.01%–60.19% 的已记录用户态周期。zrun 与 Tokio 的采样周期总量中位数约为 17.30 亿和 8.85 亿。函数级样本把优化重点指向取任务路径，仍需指令级归因才能区分本地队列、窃取扫描与内联开销。

原始报告和采样分别在 Project Z 的 `dist/zrun-e2a2d96-runtime-matrix/report.json`、`dist/zrun-e2a2d96-runtime-profile/`。比较程序 SHA-256 为 `1958c996b715a85d97e8f294538fd7f8e86d63e5cb2d78bde9dbb029f212f595`。

## 限制首次窃取扫描的实验

同一批指令采样中，窃取队列的加锁和解锁后继指令合计占 `next_task` 样本约 61%。非精确事件可能把周期归到原子指令后面，因此将两个位置归组。

本地候选 `9dab1dd` 最多允许四个 worker 同时发起首次窃取扫描。休眠前的复查保持完整。以同一主机和 CPU 0–15 比较候选与 `e2a2d96`，16 worker、100,000 任务，每格 10 对独立进程，逐轮交换顺序。80 个样本通过校验。工作区测试 110 项通过、1 项跳过。

| 指标 | 候选 / 对照及 95% 区间 |
| --- | ---: |
| 创建与回收吞吐 | 0.866 [0.837, 0.970] |
| 自唤醒吞吐 | 0.816 [0.755, 0.837] |
| 每次自唤醒 CPU | 1.271 [1.259, 1.328] |
| 自唤醒 P99 | 0.898 [0.867, 0.959] |
| 跨线程唤醒 P99 | 0.986 [0.001, 55.144] |

候选有吞吐和 CPU 开销回退，保留在实验补丁。该实验同时改变了搜索者计数和进入休眠前复查的时机，无法将回退归因于其中一项。原始数据位于 `dist/zrun-bounded-search-ab-w16/report.json`，实验补丁位于 `dist/zrun-bounded-search-experiment.patch`。

## 将首次扫描限定为两个队列

同一二进制另采 3 对 16 worker 创建与回收进程，全部通过 100,000 个任务和零活动任务校验。`SharedPool::next_task` 占 zrun 用户态周期样本的 70.21%–72.75%，直接提交任务的基准适配器占 3.11%–3.80%。原始采样位于 `dist/zrun-e2a2d96-spawn-profile/`。
